# Requirements and delivery plans

These are ordinary Markdown documents; no planning CLI or generated agent commands are required.

- `specs/`: maintained product requirements and observable scenarios.
- `changes/`: selected plans, designs, task checklists, and verification evidence.
- `changes/archive/`: historical delivery records, not current instructions.
- `backlog.md` (when present): unselected work and known gaps.
- `project-guidance.md` (when present): project context and safety/testing guidance.

Preserve checked and unchecked task status. A proposal is not proof of implementation or approval. Read repository instructions and source/tests before changing behavior; record actual validation and unresolved blockers. Update requirements and links directly when work lands. Historical records may mention retired tools; those commands are not prerequisites.
